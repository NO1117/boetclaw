# Provider 凭据保险箱与连接管理计划

## 1. 目标

将 Provider API Key 从可被控制台写入的明文 `.env` 配置升级为加密凭据保险箱，并把 Provider 配置改造成可验证、可切换、可审计的连接管理能力。任何 API、日志、Trace、错误信息和前端状态都不得返回完整密钥。

## 2. 本期范围

### 2.1 本地加密凭据保险箱

- 使用经过验证的 AEAD 算法保存凭据，禁止自制加密、Base64 伪加密或固定密钥。
- 主密钥仅从 `BOETCLAW_MASTER_KEY` 环境变量读取，不写入仓库、`.env`、workspace 或 API 响应。
- 密文记录包含 schema version、credential ID、用途、算法版本、nonce、ciphertext、创建/更新时间和非敏感标签。
- 采用原子写入、进程内锁、损坏文件隔离和严格文件权限；重启后可恢复。
- 支持创建、替换、删除、状态查询和主密钥轮换；不提供明文读取 API。
- 内存中的明文只在发起 Provider 请求或连接检测时短暂解析，不进入缓存、repr 或异常。

### 2.2 Provider 连接配置

- 将 Provider 连接与凭据分离：连接包含稳定 ID、Provider 类型、显示名称、Base URL、凭据引用、默认模型、启用状态、超时和 revision。
- 支持 OpenAI、Anthropic、Ollama 现有能力；无密钥 Provider 不创建虚假凭据。
- 支持同一 Provider 类型配置多个连接，例如生产、测试和本地代理。
- 支持创建、编辑、克隆、启停、删除、连接检测和设为默认。
- 保存前提供 validate-only；revision 乐观并发冲突返回 409。
- 更新或切换连接后只使受影响的模型/Agent 图缓存失效，不影响进行中的运行；新运行冻结连接快照。
- 连接检测使用待保存草稿或已保存凭据，返回脱敏错误分类、耗时和模型发现摘要。

### 2.3 明文迁移与兼容

- 启动时只读兼容现有环境变量，不自动改写或删除用户 `.env`。
- 提供显式“一次性导入环境变量凭据”操作；导入成功后提示用户手动清理 `.env`，不得伪称已经删除。
- 控制台保存 API Key 时只写保险箱，不再调用 `update_env_file` 写入明文。
- 未配置主密钥时：环境变量连接仍可运行；保险箱写操作明确禁用并返回可操作提示，应用不能崩溃。
- 已有默认 Provider/模型配置平滑迁移为默认连接，保持旧聊天接口兼容。

### 2.4 管理页面

- 重构“模型提供商”为“模型连接”页面：连接列表、状态、默认标识、Provider 类型、Base URL 摘要和最近检测结果。
- 新建/编辑抽屉包含 Provider、名称、Base URL、API Key、默认模型和高级参数。
- 密钥字段永不回填；仅显示“已配置”、来源（保险箱/环境变量）和末四位指纹（可安全取得时）。
- 支持显示/隐藏本次输入、粘贴保护、清空确认和保存后立即清除表单内存。
- 连接检测、保存、设为默认、删除均提供明确加载、成功和错误状态。
- Agent 配置中的 Provider/模型选择改为基于启用连接，并兼容旧 Provider 值。
- 保持当前控制台视觉体系、键盘可达性与响应式布局。

### 2.5 安全与审计

- API Key、Authorization header、密文、nonce 和主密钥不得进入日志、Trace、审计详情和测试快照。
- 审计仅记录操作者、本地请求标识、连接 ID、操作类型、结果和时间。
- 所有返回模型使用 allowlist，禁止直接序列化内部凭据对象。
- Base URL 仅允许 HTTP/HTTPS；默认阻止包含用户名密码、非法协议和明显路径穿越的 URL。
- 连接检测设置短超时、响应体上限和错误净化；不得把上游响应全文返回前端。
- 删除正在被默认配置或 Agent 配置引用的连接时返回 409，并列出非敏感引用摘要。

## 3. 明确不做

- 不实现云 KMS、HSM、团队共享密钥、多租户 RBAC 或远程密钥同步。
- 不把主密钥自动生成后写入磁盘，也不声称达到企业密钥托管等级。
- 不修改已移除的井数据模块。
- 不改变 Provider SDK 的业务行为，除连接解析和凭据注入外不重写聊天主链路。

## 4. 验收标准

1. 配置主密钥后保存 API Key，磁盘和 `.env` 中均找不到该明文，重启后连接仍可使用。
2. 未配置主密钥时保存凭据返回明确错误，但现有环境变量 Provider 仍能聊天和检测。
3. 所有 Provider/连接 API 均不返回完整密钥、密文、nonce 或主密钥。
4. 错误日志、Trace 和审计在上游返回包含密钥时仍经过净化。
5. 两个客户端同时编辑相同连接，旧 revision 保存返回 409。
6. 同一 Provider 的两个连接可以独立检测和切换默认，已有运行保持原连接快照。
7. 删除被默认连接或 Agent 引用的连接返回 409；解除引用后可删除且凭据按引用计数安全清理。
8. 显式导入环境变量凭据后，保险箱记录可用，页面明确提示 `.env` 仍需用户手动清理。
9. 主密钥轮换成功后所有凭据可用；使用旧主密钥启动无法解密并给出安全错误，不损坏数据。
10. E2E 覆盖：创建连接 → 保存凭据 → 检测 → 设为默认 → Agent 选择连接 → 密钥始终不可回读。

## 5. 质量门槛

- 前端现有 64 项 Vitest 全部通过；新增连接表单、密钥不回填、状态切换和错误处理测试。
- Playwright 现有 20 项全部通过，并新增至少一条完整连接管理流程。
- OpenAPI breaking check、`npm run build` 和 `git diff --check` 通过。
- 不提交真实密钥、密文数据、运行时保险箱、调试脚本或测试产物。
