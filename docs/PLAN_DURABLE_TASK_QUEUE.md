# 持久化任务队列与运行中心计划

## 1. 目标

将当前“内存协程 + JSON 历史文件”的后台任务升级为单机可靠任务队列，使任务在应用重启、瞬时失败和并发运行场景下具备可预测状态、自动重试、调度控制和完整运行记录。

## 2. 本期范围

### 2.1 SQLite 持久化队列

- 使用 SQLite WAL 保存任务、执行尝试、状态事件和队列租约，提供 schema version 与幂等迁移。
- 启动时显式迁移现有 `task_history.json`，保留原任务 ID、时间、结果、错误、Trace 和 Agent 信息；迁移可重复执行且不重复数据。
- 所有状态转换使用事务和条件更新，避免并发启动、重复完成和取消/完成竞态。
- 单实例 Worker 采用有期限租约领取任务；租约到期后按恢复策略重新入队或进入中断终态。
- 支持优雅关闭：停止领取新任务，给运行任务宽限期，随后安全取消并记录原因。

### 2.2 任务模型与状态

- 状态：`queued`、`scheduled`、`leased`、`running`、`retry_wait`、`cancelling`、`completed`、`failed`、`cancelled`、`dead_letter`、`interrupted`。
- 字段包含 Agent、提示词、优先级、计划时间、最大尝试次数、退避策略、超时、幂等键、连接/模型快照、知识库快照、创建来源和 revision。
- 每次尝试独立记录 attempt、开始/结束、worker ID、run/trace/thread ID、结果摘要、错误分类和耗时。
- 运行结果、错误和事件设置大小上限，超长内容安全截断并标记，不把凭据或完整敏感正文写入任务表。
- 任务更新使用 revision 乐观并发控制；冲突返回 409。

### 2.3 调度、重试和并发

- 支持立即运行与未来时间运行；时间统一持久化为 UTC，前端按本地时区展示。
- 支持固定、线性和指数退避，并加入有限 jitter；只有明确可重试错误自动重试。
- 用户取消、权限错误、配置错误、内容校验错误和安全拒绝不得自动重试。
- 支持全局并发上限、每 Agent 并发上限和每 Provider 连接并发上限。
- 相同幂等键在有效窗口内只创建一个任务，重复请求返回已有任务。
- 支持暂停/恢复队列；暂停只停止领取新任务，不强制终止运行中任务。
- dead-letter 任务可人工重新入队，生成新尝试并保留原失败链路。

### 2.4 重启恢复边界

- 未领取的 queued/scheduled/retry_wait 任务在重启后继续调度。
- leased 但未开始的任务在租约过期后重新入队。
- running/cancelling 任务重启后不得伪装为继续运行：
  - 若具备安全 checkpoint 且操作可恢复，则创建新的恢复尝试；
  - 否则标记 `interrupted`，允许用户明确重跑。
- 不声称提供跨进程 exactly-once；通过幂等创建、租约和状态条件更新实现单实例 at-least-once 防护。

### 2.5 API 与事件

- 任务创建、列表、详情、更新、取消、重跑、人工重试、暂停/恢复队列、队列统计和尝试详情 API。
- 列表支持 cursor 分页、状态、Agent、来源、时间范围和关键词筛选。
- 提供任务状态事件 SSE；断线可携带最后事件 ID 恢复，过旧游标返回可识别的重置提示。
- 保留现有任务 API 兼容路径和字段映射，旧 `pending` 映射为 `queued`。
- OpenAPI 明确 404、409、422、429 语义，所有写操作具备稳定幂等行为。

### 2.6 运行中心页面

- 将“任务与追踪”升级为运行中心：队列统计、状态分组、搜索筛选、优先级和计划时间。
- 任务详情展示状态时间线、所有尝试、重试倒计时、运行快照、结果/错误摘要以及 Trace 跳转。
- 支持新建任务、计划执行、取消、重跑、人工重试、修改尚未运行任务及队列暂停/恢复。
- 对危险或不可逆重跑给出明确确认；不可操作状态禁用按钮并解释原因。
- SSE 实时刷新，断线后回退到低频轮询并显示连接状态。
- 保持现有控制台视觉体系、键盘可达性、空状态、错误状态和响应式布局。

## 3. 安全与可观测性

- Worker 使用已冻结的 Agent、Provider 连接、模型、知识库和工具策略快照启动尝试。
- API Key、凭据 ID 的内部细节、Authorization header、完整知识库正文不得进入任务结果、错误和事件。
- 记录队列深度、领取延迟、运行耗时、成功率、重试数、dead-letter 数和租约回收数指标。
- 所有状态变化写审计/Trace，但不得重复记录完整提示词和结果。
- SQLite 路径固定在 workspace 管理目录，防止路径穿越；备份与恢复文档必须说明 WAL 一致性。

## 4. 明确不做

- 不引入 Redis、Celery、Kafka、云队列或多实例 Worker 协调。
- 不实现 DAG/可视化工作流编排、跨任务依赖或分布式 exactly-once。
- 不自动恢复无法证明安全的外部副作用操作。
- 不修改已移除的井数据模块。

## 5. 验收标准

1. 创建 10 个任务并设置全局并发 2，任意时刻最多只有 2 个运行，其余保持队列状态。
2. 相同幂等键重复创建只产生一个任务，响应返回同一任务 ID。
3. 可重试错误按策略进入 retry_wait 并最终成功；不可重试错误直接 failed。
4. 超过最大尝试次数进入 dead_letter，可人工重新入队且保留原尝试记录。
5. 计划任务在指定 UTC 时间前不领取，到时后执行；页面显示正确本地时间。
6. 取消与完成并发发生时只能产生一个合法终态，不出现 completed 后又 cancelled。
7. 重启后 queued/scheduled/retry_wait 继续工作，running 按恢复边界进入恢复尝试或 interrupted。
8. 旧 JSON 历史迁移后可查询，重复启动不产生重复记录，原文件不被自动删除。
9. Provider/Agent 并发限制生效，不同连接或 Agent 可在全局限额内并行。
10. E2E 覆盖：创建计划任务 → 提前不可运行 → 到时领取 → 模拟一次失败 → 自动重试成功 → 详情显示两次尝试和完整时间线。
