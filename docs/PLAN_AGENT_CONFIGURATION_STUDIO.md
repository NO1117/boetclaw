# Agent 配置工作室计划

## 目标

将现有只能按 ID 创建和查看的 Agent 工作区升级为可配置、可验证、可版本化、可复制和可回滚的 Agent 配置工作室，让用户无需编辑服务器文件即可安全管理 Agent 的职责、模型、提示词、工具策略、技能和运行参数。

## 当前基线

- Agent 创建接口接受自由 `config` 字典，但配置仅保存在进程内 `Workspace`，重启发现目录后会丢失。
- Agent 工作区已支持列表、文件、技能、历史、归档和彻底清理。
- 请求级模型切换、模型能力、图缓存、持久记忆和语音能力已经存在。
- 子智能体的默认配置仍由代码固定，管理端无法动态编辑。

## 本期范围

### 1. 结构化 Agent 配置

- 定义版本化 `AgentProfile`，至少包含：Agent ID、显示名称、描述、头像色、职责提示词、Provider、模型、温度、最大输出、工具策略、记忆模式、默认语言、启用状态和配置 revision。
- 严格区分用户可编辑字段与运行时只读字段；拒绝未知字段。
- Provider/模型留空表示继承全局默认，并在 API 中返回“配置值”和“有效值”。
- 工具策略至少支持：继承、仅安全工具、指定允许列表；禁止通过配置关闭平台级安全门控。
- 提示词作为低于平台安全规则的 Agent 指令，不得替代系统安全策略。

### 2. 磁盘持久化与并发控制

- 每个 Agent 在自身受控目录保存 `agent.json`，采用原子写、进程内锁、schema version 和备份。
- 服务重启和磁盘发现时恢复完整配置，不依赖进程内字典。
- 更新使用 revision 乐观并发控制；旧 revision 返回稳定冲突错误，不覆盖新配置。
- Agent ID 不可通过普通更新修改；复制时生成新 ID。
- 默认 Agent 可编辑安全字段，但不可禁用、归档或删除。

### 3. 验证、应用与运行一致性

- 保存前验证 Provider、模型能力、温度范围、输出限制、工具允许列表、提示词长度和技能引用。
- 提供 validate-only 接口，不落盘、不重建 Agent。
- 配置写入成功后精准失效对应图缓存；已加载 Agent 在锁内重建。
- 重建失败时回滚到上一版本，并保持原 Agent 可运行。
- 正在执行的 run 使用启动时配置快照，不被中途更新改变。
- API 返回最后应用状态、时间和失败摘要，不返回密钥或底层服务器路径。

### 4. 版本、复制与导入导出

- 每次成功更新生成版本记录，包含 revision、时间、变更字段和非敏感操作者信息。
- 支持查看版本、预览差异和回滚；回滚本身生成新 revision。
- 支持复制 Agent，复制配置和可选技能引用，但不复制会话、记忆、Checkpoint、任务、Trace 或文件。
- 支持导出可移植 JSON；导入必须通过同一 schema 和安全验证。
- 导出内容不得包含 API Key、服务器绝对路径、运行历史或隐私数据。

### 5. 配置 API

- `GET /api/v1/agents/{id}/profile`：配置值、有效值、revision 和应用状态。
- `PUT /api/v1/agents/{id}/profile`：带 revision 的完整更新。
- `POST /api/v1/agents/{id}/profile/validate`：仅验证。
- `GET /api/v1/agents/{id}/profile/versions`：分页版本列表。
- `GET /api/v1/agents/{id}/profile/versions/{revision}`：版本详情和差异。
- `POST /api/v1/agents/{id}/profile/rollback`：回滚指定 revision。
- `POST /api/v1/agents/{id}/clone`：复制为新 Agent。
- `GET /api/v1/agents/{id}/export`、`POST /api/v1/agents/import`：安全导出和导入。

### 6. Agent 配置工作室 UI

- 在现有 Agent 工作区增加“概览、配置、技能、文件、历史、版本”标签，不新增孤立页面。
- 创建 Agent 使用分步表单：身份、模型、行为、能力、确认；允许只填 ID 后继承默认值。
- 配置页展示继承值和有效值，模型选择复用现有能力标签与兼容说明。
- 提示词提供字符计数和安全说明，不提供绕过安全门控的开关。
- 保存前支持验证；有未保存修改时离开页面需提示。
- 版本页支持差异预览和二次确认回滚；复制、导入和导出提供明确边界说明。
- 移动和窄屏下标签可横向滚动，表单保持单列可用。

### 7. 安全与可观测性

- Agent ID、导入文件名和所有磁盘路径执行安全拼接与目录边界验证。
- 拒绝配置中出现密钥字段、私钥、Token 和连接串；日志不记录完整提示词。
- 审计记录创建、更新、验证失败、应用、回滚、复制、导入和导出，仅记录 Agent ID、revision 和变更字段。
- 指标包含保存成功/失败、验证耗时、重建耗时、回滚次数和 revision 冲突次数。

## 验收标准

1. 创建或更新 Agent 后重启服务，显示名称、提示词、模型和策略仍保持。
2. 两个客户端使用同一 revision 更新时，后提交者收到 409 冲突且不会覆盖新配置。
3. validate-only 不写磁盘、不增加 revision、不触发图重建。
4. 无效模型、越界参数、未知工具、过长提示词和含密钥字段的导入被稳定拒绝。
5. 配置应用失败自动回滚，旧 Agent 仍可继续对话。
6. 更新、回滚后图缓存精准失效；进行中的 run 保持原配置快照。
7. 复制不携带会话、记忆、Checkpoint、文件和运行历史。
8. UI 能完成创建、编辑、验证、保存、版本差异、回滚和复制闭环。
9. 后端、前端、生产构建和关闭重试的 fake Provider E2E 全部通过。

## 非目标

- 本期不实现多用户 RBAC、审批发布流或团队共享模板市场。
- 不允许用户编辑平台级系统安全提示或关闭 ToolGuard。
- 不实现任意 Python 代码、任意工具代码或任意服务器路径配置。
- 不复制 Agent 的业务数据、历史和隐私内容。
- 不修改真实 Provider 的密钥管理方式。

## 实施顺序

1. AgentProfile schema、持久化、迁移、revision 和版本仓库。
2. 验证、应用、回滚、缓存失效和运行快照。
3. 配置、版本、复制、导入导出 API。
4. Agent 工作室标签页、创建向导和配置/版本交互。
5. 单元、重启恢复、冲突、回滚和 fake Provider E2E，全量回归。
