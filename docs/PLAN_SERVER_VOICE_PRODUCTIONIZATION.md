# 服务端语音输入与输出生产化计划

## 目标

把当前仅依赖浏览器 Web Speech API 的语音体验升级为可配置、可审计、可降级的服务端语音链路，使桌面浏览器、移动浏览器及未来外部渠道都能复用统一的语音转写和语音合成能力。

## 当前基线

- 前端已支持浏览器 `SpeechRecognition` 语音输入和 `speechSynthesis` 回复朗读。
- 模型能力体系已包含 `audio_input`、`audio_output` 三态能力，但尚无语音任务 API 和服务端 Provider 抽象。
- 附件系统已有上传大小、类型、生命周期和安全边界，可复用其受控临时文件策略。
- 运行指标已支持 trace、延迟、token、估算费用和模型信息，可扩展语音阶段指标。

## 本期范围

### 1. 语音 Provider 抽象

- 新增独立的 Speech Provider 接口，包含转写（STT）和合成（TTS）能力，不与聊天模型实例强耦合。
- 首期实现 OpenAI-compatible 适配器，端点、模型、语音、格式、超时和密钥由配置提供；允许兼容本地或代理端点。
- 提供可用性与能力状态：`configured`、`unconfigured`、`unavailable`、`unknown`。
- 未配置时不得调用外网；前端自动回退现有浏览器能力。
- Provider 错误统一映射为稳定错误码，不向客户端返回密钥、上游完整响应或服务器路径。

### 2. 服务端语音转写

- 新增受认证的音频转写接口，使用 multipart 上传单个音频文件。
- 允许格式：WebM/Opus、Ogg/Opus、WAV、MP3、M4A；同时检查扩展名、MIME 和文件签名。
- 限制文件大小、最大时长、请求频率和并发数；配置项提供安全默认值。
- 音频写入受控临时目录，调用完成或失败后可靠清理。
- 返回转写文本、检测语言、时长、Provider、模型、trace id 和耗时；未知字段为 `null`。
- 不自动发送转写结果，用户可在输入框校对后再发送。

### 3. 服务端语音合成

- 新增受认证的语音合成接口，接收纯文本、语言、可选语音和输出格式。
- 限制文本长度、请求频率和并发数；拒绝空文本及不支持格式。
- 以流式音频响应或短期受控文件返回，设置正确 Content-Type、禁止缓存敏感内容。
- 支持停止播放、重新播放和下载；新回复播放时停止旧回复。
- 服务端能力不可用时回退浏览器 `speechSynthesis`，并在界面中说明当前模式。

### 4. 前端录音与播放体验

- 优先使用 `MediaRecorder` 录制音频并调用服务端转写；浏览器不支持录音或服务端未配置时使用现有实时识别。
- 录音状态包含：准备、录音中、上传中、转写中、完成、失败；显示计时、停止和取消。
- 转写结果合并到输入框但不覆盖用户已有文本，并允许撤销本次插入。
- 回复朗读支持“服务端高质量 / 浏览器本地”模式标签、播放、暂停、继续、停止和进度。
- 设置页增加语音能力状态和非敏感默认项；密钥继续走现有 Provider 安全配置方式。
- 窄屏状态不遮挡输入框，键盘和屏幕阅读器可操作。

### 5. 安全、隐私与生命周期

- 默认不持久保存原始录音和合成音频；临时文件使用随机名并在请求结束后清理。
- 日志和 trace 只记录大小、时长、格式、Provider、模型、状态和耗时，不记录音频、完整转写文本或完整合成文本。
- 服务端路径必须限制在语音临时根目录；禁止客户端传入服务器路径或 URL。
- API Token/Console JWT、现有限流和审计主体继续生效。
- 明确 UI 提示语音将发送至已配置的服务商；浏览器本地模式则标记为本地处理。

### 6. 指标与可观测性

- 记录上传、转写、合成首字节和总耗时，音频时长、输入字符数、输出字节数、Provider/模型和失败类别。
- 若上游返回 usage 或配置价格，可输出估算费用；缺失时为 `null`。
- 语音阶段与聊天使用同一 trace 体系，但不写入原始音频和完整文本。
- 提供语音 Provider 健康/能力只读接口，供设置页和聊天区选择降级策略。

## API 草案

- `GET /api/v1/voice/capabilities`：返回 STT/TTS 配置、可用性、格式和限制。
- `POST /api/v1/voice/transcriptions`：multipart 音频转写。
- `POST /api/v1/voice/speech`：文本转语音，返回流式音频。
- 错误码至少包括：`VOICE_NOT_CONFIGURED`、`VOICE_UNAVAILABLE`、`VOICE_FILE_TOO_LARGE`、`VOICE_DURATION_EXCEEDED`、`VOICE_UNSUPPORTED_FORMAT`、`VOICE_TEXT_TOO_LONG`、`VOICE_RATE_LIMITED`。

## 页面设计要求

- 保持现有深色工作区，语音入口仍位于输入框操作栏。
- 录音中使用高辨识度但克制的红色状态条，展示波形占位、时长、停止和取消。
- 上传/转写阶段锁定重复录音但不锁定文本编辑。
- 回复音频播放器嵌入对应消息，不新增独立页面。
- 设置页显示服务端与浏览器两种能力状态，不展示任何密钥值。

## 验收标准

1. 服务端已配置时，前端使用 MediaRecorder 上传并将转写追加到输入框，且不会自动发送。
2. 服务端未配置或调用失败时，可明确回退浏览器识别/朗读，已有文字不丢失。
3. 非法格式、伪造 MIME、超限文件、超长文本和越权请求均被稳定拒绝。
4. 请求成功、失败和取消后临时音频均被清理，日志不包含原始音频、完整文本或密钥。
5. TTS 支持播放、暂停、继续、停止；切换回复时旧音频停止并释放对象 URL。
6. 能力接口、转写、合成、降级、取消和清理均有自动化测试。
7. 后端、前端、生产构建和关闭重试的 E2E 全部通过。

## 非目标

- 本期不实现实时双向语音通话或 WebRTC 会话。
- 不做说话人分离、声纹识别、声音克隆和情绪识别。
- 不长期保存录音、建立语音资料库或对音频做全文检索。
- 不要求所有聊天模型原生支持音频；STT/TTS 与聊天模型保持解耦。
- 不在测试中调用真实付费服务。

## 实施顺序

1. 实现配置、Provider 抽象、能力接口和安全校验。
2. 实现 STT 上传、临时文件生命周期和指标。
3. 实现 TTS 流式响应、取消和指标。
4. 按 Figma 设计改造录音、转写、消息播放器和设置状态。
5. 补齐单元、契约和 fake Provider E2E，执行完整回归。
