# PLAN-800：附件与长文档生产化

## 1. 目标

将当前“请求内 Base64 附件”升级为可持续使用的附件系统，使用户能够可靠上传、解析、检索和删除真实工作资料，并让 Agent 按模型能力安全读取附件。

本计划在现有多模态聊天、Agent 工作区、Provider、Trace 和审批能力上增量实现，不重写聊天主链路。

## 2. 当前基线

- 前端支持文件、图片、文件夹选择和拖放，限制为单文件 25 MB、单次 20 个、总计 100 MB。
- 文本和图片可进入聊天请求；普通二进制文件仅发送元数据。
- 当前请求使用 Base64 JSON，缺少上传进度、复用、生命周期和长文档检索。
- 前端 Vitest 47 项、后端 pytest 223 项、Playwright 9 项通过。
- 工作区存在未提交改动，实施时必须保留并在其上增量修改。

## 3. 本期范围

### 3.1 两阶段附件协议

1. 新增附件上传、查询、内容读取和删除 API。
2. 上传成功返回稳定的 `attachment_id`；聊天请求优先携带 ID，不再重复发送 Base64。
3. 保留现有内联附件字段作为兼容路径，但前端默认使用新协议。
4. 附件必须归属具体 Agent；不同 Agent 不能互相读取。
5. 保存 SHA-256、原始名称、相对路径、MIME、大小、状态、创建时间和过期时间。

### 3.2 文档解析

本期支持：

- 纯文本、Markdown、JSON、YAML、CSV、代码文件。
- PDF 文本与页码。
- DOCX 段落和表格。
- XLSX 工作表与单元格值；公式保留公式文本和已缓存值（可用时）。
- PPTX 幻灯片正文和备注（可用时）。

解析失败不能导致上传记录丢失；状态应为 `failed`，保留安全错误摘要并允许重试。

扫描 PDF OCR、复杂版面复原、宏执行、嵌入对象执行不在本期范围。

### 3.3 分块与检索

1. 将解析文本按标题、页、工作表或幻灯片边界优先分块。
2. 块记录包含来源位置和顺序，可生成可追溯引用。
3. 本期实现本地关键词检索；复用项目现有存储方式，不引入独立向量数据库。
4. 聊天只注入与问题相关的块和附件摘要，避免将完整长文档塞入上下文。
5. Trace 记录选中的附件 ID、块 ID、位置和截断信息，但不记录原始二进制或完整敏感文本。

### 3.4 生命周期与安全

- 状态：`uploading`、`uploaded`、`parsing`、`ready`、`failed`、`expired`、`deleted`。
- 上传时同时检查声明 MIME、文件签名、扩展名和大小。
- 文件名和相对路径必须正规化，拒绝路径穿越。
- 禁止执行文档宏、脚本、嵌入文件或压缩包内容。
- 删除采用记录 tombstone + 删除原始文件和解析产物；删除操作写入审计/Trace。
- 默认过期时间可配置；增加清理服务，但不得删除仍被有效会话引用的附件。
- 原始文件、Base64 和完整解析内容不得进入普通日志或异常响应。

病毒扫描仅预留明确接口和 `scan_status` 字段；没有扫描引擎时显示“未扫描”，不得伪装为安全。

### 3.5 前端体验

- 附件进入上传队列后显示真实上传与解析进度。
- 支持取消、失败重试、移除和已上传附件复用。
- 发送按钮仅在附件达到可发送状态时启用。
- 图片发送前根据当前模型能力校验。
- 长文档显示页数/工作表/幻灯片数量、解析状态和可检索状态。
- 会话消息展示附件卡片和引用位置，不显示虚假“已解析”状态。
- 保持现有 Figma `01 · Chat Workspace v2` 的视觉体系和响应式规则。

## 4. 明确不做

- 多租户、RBAC、付费配额和团队共享。
- 云对象存储、分布式任务队列和多实例一致性。
- 独立向量数据库或语义重排平台。
- OCR、音视频理解、ZIP/RAR 解压。
- 文档在线编辑和 Office 格式原样渲染。
- 修改已经移除的井数据前端页面。

## 5. 技术实施顺序

1. 定义附件领域模型、Agent 隔离目录和元数据存储。
2. 实现上传/查询/删除/重试 API 与安全校验。
3. 实现解析器注册表以及 PDF、DOCX、XLSX、PPTX 解析器。
4. 实现分块、关键词索引和上下文选择。
5. 将聊天请求迁移到 `attachment_ids`，保留旧字段兼容。
6. 更新前端上传队列、进度、状态、复用和引用展示。
7. 补齐 API 文档、架构文档、依赖和测试。

## 6. 验收标准

### 上传与隔离

- Given 用户为 Agent A 上传文件，When 使用 Agent B 查询该 ID，Then 返回 404 或无权限，不泄露元数据。
- Given 上传合法 PDF/DOCX/XLSX/PPTX，When 上传完成，Then 返回附件 ID，并可观察 `uploaded → parsing → ready` 状态。
- Given 文件超过限制、MIME/签名不匹配或路径非法，When 上传，Then 服务端拒绝且不留下半成品文件。

### 解析与检索

- Given 支持的办公文档，When 解析成功，Then 可查询结构摘要与带来源位置的文本块。
- Given 超长文档和相关问题，When 发起聊天，Then 只注入命中的有限文本块，并在 Trace 中记录引用。
- Given 解析失败，When 用户重试，Then 状态重新进入 `parsing`，失败原因不会暴露服务器路径或文件内容。

### 生命周期

- Given 已上传附件，When 用户删除，Then 原始文件、解析结果和索引被删除，记录进入 tombstone 状态。
- Given 附件已被有效会话引用，When 清理任务运行，Then 不删除该附件。
- Given 没有病毒扫描引擎，When 查看附件，Then UI 明确显示“未扫描”。

### 聊天与兼容性

- Given 旧版内联附件请求，When 调用聊天 API，Then 保持兼容。
- Given 新版 `attachment_ids` 请求，When 同步或流式聊天，Then Agent 读取相同的解析/图像内容。
- Given 图片附件和非视觉模型，When 发送，Then 前后端均阻止请求并提示更换模型。
- Given 纯附件消息，When 附件 ready，Then 可以发送且会话历史只保存摘要和 ID。

### 质量门槛

- 前端现有 47 项测试、后端现有 223 项测试、Playwright 现有 9 项测试全部保持通过。
- 新增后端测试覆盖上传、隔离、格式解析、失败重试、删除、清理、检索和兼容请求。
- 新增前端测试覆盖上传进度、取消、失败重试、状态门禁和消息附件展示。
- 新增至少一条 E2E：上传文本/文档 fixture → 等待 ready → 通过附件 ID 发送 → 页面显示引用。
- `npm run build`、`git diff --check` 通过；测试使用 `backend/.venv`。

## 7. 风险与降级

- Office/PDF 解析库缺失时，启动检查应明确指出缺少依赖，不允许静默退化为“已解析”。
- 解析采用后台任务时必须有单进程可用实现；不得为了本期目标引入外部队列。
- 大文档处理必须设置文本字符、块数量和处理时间上限。
- 若模型上下文容量不足，优先减少检索块并返回截断信息，不能无限扩充 Prompt。
- Windows 和 Linux 路径行为均需测试，存储路径不得依赖当前工作目录。
