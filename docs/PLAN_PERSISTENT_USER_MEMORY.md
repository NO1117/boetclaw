# 长期记忆持久化与用户可控管理计划

## 目标

将当前仅在进程内生效的长期记忆升级为单实例可持久化、可检索、可解释、可编辑和可删除的用户记忆系统，使 Agent 在服务重启后仍可安全复用用户明确允许保存的信息。

## 当前基线

- `MEMORY_BACKEND=store` 当前使用 LangGraph `InMemoryStore`，进程重启后丢失。
- 默认文件记忆可读取 `AGENTS.md`，但不适合动态保存和用户管理。
- 会话、计划、Checkpoint、Trace 已有各自持久化机制。
- `cron`、`heartbeat` 已被上下文策略标记为不得污染长期记忆。
- 当前没有用户可见的记忆列表、搜索、编辑、删除和来源解释。

## 本期范围

### 1. 持久化记忆存储

- 新增 SQLite 长期记忆仓库，数据库位于受控 workspace 目录，启动时自动初始化 schema。
- 每条记忆至少包含：稳定 ID、Agent ID、作用域、内容、摘要、标签、来源类型、来源 thread/trace、创建时间、更新时间、最后使用时间、使用次数和状态。
- 支持按 Agent 隔离；默认 Agent 不得读取其他 Agent 的私有记忆。
- 写入具备事务、并发锁、schema version 和安全迁移；提供关闭、备份和健康状态。
- `memory` 降级仅在配置明确允许时启用，并在健康接口中标记为不持久。

### 2. 记忆作用域和策略

- 作用域至少包括：Agent 私有、线程私有；本期不实现跨用户或跨租户共享。
- 自动记忆模式：`off`、`review`、`auto`，默认 `review`。
- 只有用户交互来源可产生候选记忆；`cron`、`heartbeat`、系统提示、工具原始输出和错误堆栈不得自动写入。
- 候选类型限制为用户偏好、稳定事实、长期目标和明确约束；一次性问题、敏感凭据和大段文档内容不得自动保存。
- `review` 模式下候选必须由用户确认；`auto` 模式仍需通过敏感信息与重复检测。
- 用户明确说“记住”“忘记”时优先执行显式意图，并返回可见确认。

### 3. 检索与上下文注入

- 支持关键词、标签、作用域和更新时间过滤；SQLite FTS5 可用时启用全文检索，不可用时安全降级。
- 注入上下文前执行去重、相关性排序、条数和字符预算限制。
- 注入内容以独立“用户记忆”上下文块提供，不伪装成系统指令，不覆盖更高优先级安全规则。
- 每次命中更新使用次数和最后使用时间，但不得把本次模型输出再次写成重复记忆。
- 前端运行上下文展示本次使用的记忆数量；允许用户查看具体来源。

### 4. 记忆管理 API

- `GET /api/v1/memories`：分页列表与搜索。
- `POST /api/v1/memories`：用户手动新增。
- `GET /api/v1/memories/{id}`：详情和来源元数据。
- `PATCH /api/v1/memories/{id}`：编辑内容、标签、作用域或状态。
- `DELETE /api/v1/memories/{id}`：删除单条记忆。
- `POST /api/v1/memories/{id}/approve|reject`：审核候选记忆。
- `POST /api/v1/memories/bulk-delete`：按明确筛选条件批量删除，禁止无条件误删。
- `GET /api/v1/memories/export`：导出用户可读 JSON，不包含数据库路径和内部凭据。

### 5. 用户界面

- 设置区新增“长期记忆”页面，包含搜索、作用域/状态过滤、分页列表、编辑、删除、候选审核和导出。
- 聊天上下文栏增加记忆摘要卡：当前模式、已保存数量、本次使用数量和待审核数量。
- 聊天中出现候选记忆时使用轻量确认条，支持“保存”“忽略”“编辑后保存”。
- 删除与批量删除必须二次确认；成功后立即从当前上下文与列表移除。
- 空态、禁用态、降级态和存储异常都提供明确中文说明。

### 6. 安全与隐私

- 对 API Key、Token、密码、Cookie、私钥、连接串和常见凭据模式执行拒绝保存或脱敏。
- 限制单条长度、标签数量、查询长度、分页大小和每 Agent 总量。
- 日志和 Trace 只记录 memory ID、作用域、状态、命中数和耗时，不记录完整记忆正文。
- 所有路径固定在配置的记忆根目录，客户端不得传入服务器路径。
- 删除后不得继续从进程缓存返回；备份保留策略必须在文档中说明。

### 7. 可观测性

- 记录记忆创建、审核、检索、命中、跳过、去重、删除和存储错误计数。
- 记录检索耗时、候选数、注入条数和字符预算，不记录正文。
- 健康接口返回 backend、persistent、schema version、数据库可写性和最后错误摘要。

## 验收标准

1. 保存记忆后重建服务和 Agent，仍可检索并在符合条件的后续对话中使用。
2. 相同 thread ID 在不同 Agent 下不能读取对方私有记忆。
3. `cron`、`heartbeat`、工具输出和明显凭据不会生成自动候选。
4. `review` 模式候选未经批准不会注入上下文；批准后可被检索，拒绝后不可被检索。
5. 编辑、删除和批量删除立即生效；删除后进程缓存与检索结果均不存在旧内容。
6. 搜索、分页、过滤、导出和来源展示可用，且不暴露服务器路径或密钥。
7. 上下文注入严格遵守条数和字符预算，重复记忆不会重复注入。
8. 后端、前端、生产构建和关闭重试的 fake Provider E2E 全部通过。

## 非目标

- 本期不实现多用户、组织、租户共享记忆。
- 不实现向量数据库、云端 Embedding 服务或跨实例一致性。
- 不把原始附件全文、音频、图片或工具结果保存为长期记忆。
- 不保证模型自动抽取结果绝对正确；用户始终可查看、修改和删除。
- 不替代 LangGraph Checkpoint、会话历史或 `AGENTS.md` 静态规则。

## 实施顺序

1. SQLite schema、仓库、迁移、健康和配置。
2. 作用域、敏感信息、去重、审核和检索策略。
3. Agent 检索注入与显式记住/忘记意图闭环。
4. 记忆管理 API 与前端管理页面、上下文卡、候选确认条。
5. 单元、契约、重启恢复和 fake Provider E2E，最后执行全量回归。
