# 团队身份与资源权限实施计划

## 1. 目标

将现有单一 Console 密码升级为适合单工作区团队使用的本地账号体系，提供用户、角色、会话撤销、资源级授权和可追溯审计，同时保持默认本地开发和现有 API Token 的兼容性。

本期是“单实例、单工作区、多用户”，不是多租户平台。

## 2. 身份与会话

### 2.1 用户账号

- 用户字段：稳定 ID、用户名、显示名称、状态、系统角色、密码摘要、token version、创建/更新时间、最后登录时间。
- 用户名采用规范化唯一规则，避免大小写、空白和 Unicode 混淆。
- 密码使用成熟库的 Argon2id 哈希；禁止明文、可逆加密、自制哈希或仅 SHA-256。
- 支持创建、编辑、禁用、重新启用、重置密码和强制注销全部会话。
- 禁止删除或禁用最后一个有效 owner；用户删除采用 tombstone，审计记录保留。
- 登录失败采用账号/IP 双维度限流和递增短暂锁定，响应不泄露账号是否存在。

### 2.2 会话

- JWT/会话包含 user ID、角色、token version、session ID、签发与过期时间。
- 服务端持久化会话记录，支持单会话注销、全部会话注销、密码变更后撤销旧会话。
- Cookie 使用 HttpOnly、SameSite=Lax；生产 HTTPS 配置可启用 Secure。
- 对 Cookie 鉴权的写操作增加 CSRF token 校验；Bearer/API Token 请求不使用 Cookie CSRF。
- `/auth/me` 返回安全用户摘要和权限集合，不返回密码摘要、内部密钥或会话令牌。

## 3. Bootstrap 与兼容

- 空用户库首次启动进入 bootstrap 状态，只允许本机或显式 bootstrap token 创建首个 owner。
- 现有 `CONSOLE_PASSWORD` 可作为一次性兼容登录入口；owner 创建成功后页面提示停用该环境变量，但不自动修改 `.env`。
- 没有用户且未配置任何鉴权时保持可信本地开发模式，但 UI 明确标记“开放模式”。
- 现有 `API_TOKEN` 保持兼容，作为受审计的 legacy service principal；默认具备管理员级权限，但不能管理 owner 或读取凭据明文。
- 不破坏现有登录接口；旧密码请求可映射到兼容登录，前端升级为用户名+密码。

## 4. 角色与权限

### 4.1 系统角色

- `owner`：完整管理权限、用户与角色、Provider 凭据、系统安全设置。
- `admin`：管理用户（不能授予 owner）、Agent、知识库、任务和运营设置。
- `operator`：使用授权 Agent、管理授权知识库、创建和操作自己的任务、审批允许范围内的工具。
- `viewer`：只读访问被授权资源、运行结果和脱敏监控信息。

权限使用明确 permission code，不在路由中散落角色名称判断。角色和权限映射集中定义并测试。

### 4.2 资源授权

- Agent 和知识库支持 `owner_user_id`、可见范围（private/workspace）和用户授权（viewer/editor/runner）。
- 任务自动记录创建者；只有创建者、资源授权用户或管理员可查看和操作。
- 会话、附件、记忆、文件和 Trace 继承对应 Agent/任务的访问边界。
- Provider 连接与凭据管理仅 owner/admin 可见；普通用户只能看到可选连接的脱敏名称和模型能力。
- 工具审批必须校验当前用户对对应 Agent/任务的 runner 权限，不能仅凭 approval ID 操作。
- 对无权限资源统一返回 404，避免枚举；权限足够但状态冲突才返回 409/403。

## 5. 持久化与审计

- 使用 SQLite WAL 保存用户、角色映射、会话和资源授权，具备 schema migration、事务和备份说明。
- 所有授权决策基于请求上下文中的 actor，不信任客户端传入的 user ID。
- 审计记录 actor、操作、资源类型/ID、结果、请求关联 ID、时间和来源类型；不记录密码、token、API Key、完整提示词或正文。
- 用户禁用、角色变化、权限授予/撤销、登录失败、会话撤销、Provider 管理和危险审批均进入审计。
- 提供带 cursor 的审计查询，仅 owner/admin 可访问；普通用户可查看自己的登录和会话活动。

## 6. API 与前端

### 6.1 API

- Bootstrap、登录、刷新/续期、登出、当前用户、修改密码和会话管理。
- 用户 CRUD、角色调整、密码重置、强制注销。
- Agent/知识库授权列表、授权、撤销和可见范围更新。
- 审计查询和个人安全活动。
- OpenAPI 为所有受保护操作声明 401/403/404/409/429，并保持旧客户端兼容。

### 6.2 前端

- 登录页升级为用户名+密码，并覆盖 bootstrap、锁定、过期和开放模式。
- 增加“团队与权限”页面：用户列表、邀请式创建、角色、状态、密码重置和会话撤销。
- Agent 配置工作室和知识库详情增加“访问权限”标签，支持范围与成员授权。
- 顶部用户菜单展示当前用户、角色、修改密码、会话和退出。
- 所有操作按钮按权限隐藏或禁用，但后端仍是最终权限边界。
- 401 自动回到登录；403/404/409 使用不同的非泄露提示；保留深链返回。
- 保持现有控制台视觉体系、键盘可达性和响应式布局。

## 7. 安全边界

- 不在 localStorage 保存长期会话令牌；优先 HttpOnly Cookie，前端只持有短期 CSRF token。
- 密码、JWT、session ID、CSRF token、密码摘要不得进入日志、Trace、审计详情和错误响应。
- 权限检查必须覆盖同步聊天、SSE、任务、审批、附件、知识库、记忆、Agent 文件、Provider 和管理 API。
- SSE 建立连接时校验权限，恢复游标不能绕过资源授权。
- 默认 owner/admin 的高风险操作需要二次确认；不伪装为操作系统级隔离。

## 8. 明确不做

- 不实现组织/租户隔离、SSO、OIDC、SAML、LDAP、邮件邀请或密码找回邮件。
- 不实现自定义角色编辑器；本期使用固定系统角色和资源授权级别。
- 不实现跨实例会话同步或外部身份数据库。
- 不修改已移除的井数据模块。

## 9. 验收标准

1. 首次 bootstrap 创建 owner 后，旧开放写接口立即需要认证。
2. 密码摘要为 Argon2id，数据库、API、日志和浏览器状态均无明文密码。
3. 禁用用户或执行“注销全部会话”后，其旧 Cookie/JWT 立即失效。
4. viewer 无法创建任务、修改 Agent、管理知识库或批准工具；越权资源返回 404。
5. operator 只能使用授权 Agent，并只能查看/取消自己的任务。
6. admin 可以管理普通用户，但不能创建、降级、禁用或删除 owner。
7. 最后一个 owner 无法被禁用、降级或删除，并发请求下仍由事务保证。
8. private Agent/知识库仅 owner、授权成员和管理员可见；workspace 资源按角色权限可见。
9. Cookie 写请求缺少或错误 CSRF token 时被拒绝；Bearer/API Token 调用保持兼容。
10. E2E 覆盖：bootstrap owner → 创建 operator/viewer → 授权 Agent → operator 成功运行任务 → viewer 越权被拒绝 → 强制注销 operator 后旧会话失效。
